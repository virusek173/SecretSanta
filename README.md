# 🎅 Secret Santa

A Secret Santa gift exchange application with AI integration.

## ✨ Features

- 🎲 Secret Santa assignment algorithm (single cycle, nobody draws themselves)
- 🤖 Personalized messages in Polish generated by OpenAI `gpt-5.6-terra`
- 🎨 Unique Christmas images generated by OpenAI `gpt-image-2`
- 📧 HTML emails via Resend with the drawn person's name, message and inline image
- 🔁 Resumable runs: draw → generate → send, with progress saved after every step
- 🔍 Spoiler-free verification of the draw before anything is sent
- 🙈 Nobody (including the organizer) sees the pairs: logs never pair names and the saved draw is encrypted and deleted after sending
- ✅ Input data validation (email, participants)
- 🧪 Unit tests (Jest) and GitHub Actions CI

## 📋 Requirements

- Node.js >= 20
- OpenAI account with API key
- Resend account (free plan: 100 emails/day) and a domain you can add DNS records to.
  We moved off SendGrid because it no longer has a free plan, see
  [docs/decisions/0001](docs/decisions/0001-resend-instead-of-sendgrid.md).

## 🚀 Installation

1. Clone the repository and install dependencies:
```bash
git clone <repository-url>
cd SecretSanta
npm install
```

2. Configure environment variables:
```bash
cp .env.example .env
```

Fill in the `.env` file:
```env
OPENAI_API_KEY=sk-...
RESEND_API_KEY=re_...
EMAIL_FROM=santa@your-domain.com   # or: Santa <santa@your-domain.com>

# Optional – override models when OpenAI retires the defaults
# OPENAI_TEXT_MODEL=gpt-5.6-terra
# OPENAI_IMAGE_MODEL=gpt-image-2
```

**Setting up Resend:**
1. Sign up at https://resend.com (free plan, no card).
2. Domains → Add Domain → enter your domain. Add the records Resend lists at your DNS
   provider (DKIM TXT `resend._domainkey`, MX and SPF TXT on `send`), then click Verify.
   Your root SPF and MX records stay as they are.
3. API Keys → Create API Key. "Sending access" is enough; "Full access" also lets the
   app check, before the draw, that your sender domain is verified.
4. `EMAIL_FROM` can be any address in the verified domain; it needn't be a real mailbox.
   The sender name defaults to "Święty Mikołaj".

3. Create the participants file:
```bash
cp config/participants.json.example config/participants.json
```

```json
{
  "participants": [
    {
      "name": "John Doe",
      "email": "john@example.com",
      "description": "Loves fantasy books and good coffee"
    }
  ]
}
```

## 📖 Usage

### Run the draw and send emails
```bash
npm run santa
```

A run has three phases:

1. **Draw** – pairs are assigned and saved, encrypted, in `state/`.
   A verification report is printed (see below) and you are asked to confirm.
2. **Generate** – messages and images are created for everyone. Progress is saved after each one.
3. **Send** – emails go out one by one; each successful send is recorded.
   Temporary errors (rate limits, 5xx, network) are retried automatically; each email
   carries an idempotency key, so a retry can't deliver it twice.

When every email has been sent, `state/` is deleted and the pairs exist only in the participants' inboxes.

### If something fails
```bash
npm run santa:resume   # continue the saved draw – no re-draw, no regenerating finished content
npm run santa:fresh    # discard the saved draw and start over
```

A plain `npm run santa` refuses to start while an unfinished draw is saved, so you can't
accidentally re-draw after some people already got their email. `--resume` also refuses if
`participants.json` changed since the draw.

### Verification report

Before generating anything, the app prints a report that lets a human check the draw
without spoiling it:

```
🔍 Draw verification (no names revealed)
   Draw code:                   #3D1E
   Participants:                5
   Everyone gives exactly once: ✓
   Everyone gets exactly once:  ✓
   Nobody drew themselves:      ✓
   Structure:                   one cycle of 5
   Masked gift graph:
      [USER-2269A46B] → [USER-3CF7FF80]
      [USER-3CF7FF80] → [USER-92D7D201]
      [USER-92D7D201] → [USER-CD7F4ECD]
      [USER-CD7F4ECD] → [USER-D7F81C50]
      [USER-D7F81C50] → [USER-2269A46B]
   Email recipients:            Anna Kowalska, Jan Nowak, Katarzyna Dąbrowska, Maria Wiśniewska, Piotr Zieliński

Generate content and send 5 email(s)? [y/N]
```

- The graph uses hashes with a random key created for that run only; the name → hash mapping is never shown.
- The recipient list shows who gets an email, not whom they drew.
- Every email contains the **draw code**, so participants can tell an email from an old, abandoned run.
- Each participant can check for themselves that they didn't draw themselves.

For unattended runs (no terminal), pass `--yes` to skip the confirmation.

### Dry-run (preview without sending)
```bash
npm run santa:dry-run            # with images
npm run santa:dry-run-no-images  # faster and cheaper
```

Messages and images are written to `output/`. ⚠️ The preview reveals every pair, and a
dry-run draw is never reused for the real run.

### All options
```bash
node dist/index.js [--dry-run] [--no-images] [--encrypt-logs] [--resume | --fresh] [--yes]
```

| Option | Effect |
|---|---|
| `--dry-run` | Generate and save to `output/` instead of sending |
| `--no-images` | Skip image generation |
| `--encrypt-logs` | Mask names and emails in progress logs |
| `--resume` | Continue an unfinished draw |
| `--fresh` | Discard an unfinished draw and draw again |
| `--yes` | Don't ask for confirmation before sending |

### Tests, build, lint
```bash
npm test
npm run build
npm run lint
```

## 🔒 Security & privacy

- Credentials stored in `.env` (not committed)
- Resend key (and, with a full-access key, the sender domain) checked before the draw
- Logs never print who drew whom
- The saved draw (`state/`) is AES-256-GCM encrypted and deleted after the last email.
  This keeps the pairs out of sight; it can't stop someone determined who runs the
  program, since the key is stored next to the state.
- AI-generated text is HTML-escaped before being put into the email
